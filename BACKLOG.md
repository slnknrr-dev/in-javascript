# BACKLOG — pipeline артефактов и инструмент `downgrade`

Источник истины для CI/CD и для самописного «babel».
Правила из [CODE_STRUCTURE.md](CODE_STRUCTURE.md), [FILE_NAMING.txt](FILE_NAMING.txt),
[IMG-FORMATS.txt](IMG-FORMATS.txt), [README.txt](README.txt) здесь не переписываются,
а дополняются; расхождения вынесены в §12.

Состояние помечено по месту: **[готово]** — написано и покрыто тестами,
**[M<n>]** — запланировано на такой-то этап §11.

## 0. TL;DR

- Монорепо сниппетов. **Исходники** — es16+ (ES2025+), ESM, DRY через `import`/`export`
  helper'ов и `algorithm/`.
- **CI/CD** (Forgejo Actions на Codeberg; git-объекты **sha256**) кладёт рядом с каждым
  исходником — *там, где лежат реальные файлы* — подпапки-цели: `png.@image/es6@mjs/`,
  `png.@image/es5@cjs/`, `@.typescript/math.@num/es6@ts/` и т. д.
- В каждой папке цели — **два singlefile-артефакта** на исходник: `<name>.js` (читаемый)
  и `<name>.min.js` (минифицированный). Для `@ts`-целей — `.ts`/`.min.ts`.
- В шапке артефакта — **хеш дерева** и построчно все файлы, из которых он собран, с их
  хешами. Хеш считается по тексту **без комментариев**: правка комментария не
  пересобирает артефакт, правка кода — пересобирает.
- Всё это делает **самописный babel** — `@slnknrr/downgrade`: vanilla Node.js ≥ 21,
  zero dependencies, лежит в репо как виртуальная devDependency (`.devdeps/downgrade/`),
  запускается из top-level `package.json`.
- Понижение — **заменой текста в диапазонах узлов**, а не печатью файла из AST: всё,
  что проход не трогал, включая комментарии, переносится байт в байт. Цель, которую
  понизить нельзя или ещё нечем, не собирается — это не ошибка, а строка отчёта с
  причиной (`unsupported` / `pending`).

## 1. Термины

| термин | значение |
|---|---|
| **сниппет** | один `.js`/`.ts` в тематической папке; тема файла = тема папки, ничего лишнего |
| **helper** (`*-helper.js`) | файл без самостоятельной ценности, существующий ради инлайна 1-в-1 в потребителей. Живёт **рядом со своей темой** (`image/buffer-helper.js`). Своих артефактов не имеет |
| **algorithm** (`algorithm/*.js`) | переиспользуемый алгоритм, осмысленный **за пределами явной предметной области**. Импортируется сниппетами, инлайнится в их артефакты, **и сам является сниппетом** — имеет свои артефакты. Критерий — §3 |
| **движок** `.@<engine>` | `.@nodejs`, `.@bun`, `.@deno` |
| **диалект** `@.<dialect>` | `@.typescript`, `@.coffeescript` (второй — только в теории, ничего особого не делаем) |
| **target** | `<профиль>@<модули>`: `es5@cjs`, `nodejs18@cjs`, `es6@ts`. Профиль = уровень синтаксиса + таблица runtime-примитивов + (для nodejs) уровень node-API |
| **артефакт** | результат для пары (исходник × target), в двух вариантах: обычный и `.min`. Без `import`/`require` чего-либо, кроме встроенных модулей node (и то — только в `nodejs*`) |
| **singlefile** | helper'ы, `algorithm/*` и runtime-шимы заинлайнены; артефакт копируется куда угодно и работает |
| **runtime primitives downgrade** | замена/шимирование встроенных (`Object.assign`, `Array.prototype.at`, `Map`, `Promise.withResolvers`, `Buffer`, `crypto.getRandomValues`, …), которых нет в профиле |
| **codeHash** | sha256 нормализованного текста файла (без комментариев и лишних пробелов) **[готово]** |
| **treeHash** | sha256 по списку «путь codeHash» всех файлов дерева импортов + цель + версия схемы. Стоит в шапке артефакта **[готово]** |
| **t9n** | `.t9n/<lang>/<путь-как-в-корне>/README.md` — зеркало документации. Оригинал — английский README у исходников |
| **NOTICE** | `*_NOTICE.md` рядом с файлами — инструкции CI/CD по переброске в другие репозитории |
| **профиль** | что цель умеет сама: редакция стандарта (`es6` = ES2015) и, у nodejs-целей, возможности сверх неё и версия node ([profiles.js](.devdeps/downgrade/src/profiles.js)) **[готово]** |
| **проход** | понижение одной возможности языка (`?.`, поля классов, …) заменой текста в диапазонах узлов ([passes/](.devdeps/downgrade/src/passes/)) **[готово]** |
| **помощник** | функция runtime-блока, которую зовёт понижённый код (`__dg_privGet`, `__dg_objectSpread`); ничего не меняет в глобальных объектах **[готово]** |
| **шим** | guarded polyfill примитива, которого нет у цели (`Array.prototype.at`); ставится, только если его нет **[готово]** |
| **полифил-сниппет** | полифил, который в шим не влезает (Symbol, WeakMap, TypedArray): живёт в репозитории обычным сниппетом и собирается во все цели, а инструмент втягивает его в артефакт в режиме `inline`, предпочитая нативное (§6.7g) **[готово]** |
| **витрина** | файл темы из одних `export … from`: одна точка входа на папку (`arraybuffer/arraybuffer.js`, `symbol/symbol.js`, `weakmap/weakmap.js`) **[готово]** |
| **pending / unsupported** | цель не собирается: проход ещё не написан (с этапом) / понизить нельзя в принципе (с причиной). Не ошибка сборки |

## 2. Инварианты (проверяются `npm run lint`)

1. Исходники — **только ESM**. `@.typescript` — 100 % ESM. **[готово]**
2. Версия языка **исходника не ограничена** и не может быть ограничена (CODE_STRUCTURE).
   Уровень задаётся только именем папки артефактов.
3. Импорты в исходнике допускаются только: относительные на `*-helper.js` и на
   `algorithm/*.js`; `node:*` — только в движковом коде. Bare-, URL-, `npm:`/`jsr:`- и
   динамические импорты — ошибка: singlefile из них не собрать. **[готово]**
4. `algorithm/*.js` импортирует только другие `algorithm/*.js` и обязан начинаться
   комментарием-шапкой с именем алгоритма. **[готово]**
5. `*-helper.js` не порождает артефактов и не обязан быть самодостаточным. **[готово]**
6. Папки артефактов (`/^(es|nodejs)\d+@(cjs|mjs|ts)$/`) содержат **только
   сгенерированное**: каждый файл начинается со штампа. Ручной файл = ошибка. **[готово]**
7. Генерация **детерминирована и идемпотентна**: два прогона — байт-в-байт одно и то же
   (в штампе хеши, не даты; LF; posix-пути; свежие имена — функция занятых имён, а
   не счётчика прогонов). **[готово]**: повторный `emit` не трогает ни одного из 164
   файлов, `render` и `lower` проверены тестами на повторяемость.
8. `.t9n/` зеркалит только документацию; артефактов внутри нет; инструмент её не
   сканирует. **[частично: не сканирует — готово; проверка зеркальности — M2]**
9. Имена файлов — по [FILE_NAMING.txt](FILE_NAMING.txt). Один dot-шаг на уровень. **[M2]**
10. Пустой исходник — `empty`, пропускается. Исходник без `export` — `no-exports`
    (предупреждение). Текстовая заметка в `.js` — `note`. **[готово]**

## 3. helper или algorithm — как решать

Вопрос не «переиспользуется ли», а **«осмысленно ли это вне своей предметной области»**.

- `permutations` — да: комбинаторика нужна не только там, откуда её достали. → `algorithm/`
- `fillBufferWithRGB` — нет: он про пиксели. Даже если его зовут из PNG, JPEG, MP4 и GIF,
  это всё та же область. → helper рядом с темой.

Проверка формулируется так: *назови область, в которой это пригодится и которая не
является ни изображениями, ни видео.* Не называется — значит helper.

### Что по этому правилу вынесено из png/jpg/gif **[готово]**

| куда | что | область за пределами изображений |
|---|---|---|
| [algorithm/crc32.js](algorithm/crc32.js) | CRC-32/ISO-HDLC | zip, gzip, Ethernet FCS, SATA, Modbus |
| [algorithm/adler32.js](algorithm/adler32.js) | Adler-32 (RFC 1950) | хвост любого zlib-потока: woff, PDF, loose-объекты git |
| [algorithm/inflate.js](algorithm/inflate.js) | inflate RFC 1951 + zlib RFC 1950 | gzip, zip, HTTP Content-Encoding, jar, docx/odt, packfile git |
| [algorithm/deflate-stored.js](algorithm/deflate-stored.js) | DEFLATE одними stored-блоками | заведомо читаемые .zip/.gz/PDF без компрессора |
| [algorithm/lzw.js](algorithm/lzw.js) | LZW переменной длины, LSB-first | PDF LZWDecode, Unix compress |
| [algorithm/dct8.js](algorithm/dct8.js) | 8×8 DCT-II и обратное | MP3/AAC, MPEG/H.26x, спектральный анализ, ДУ на сетке Чебышёва |
| [image/buffer-helper.js](image/buffer-helper.js) | UIB core v1 — раскладка буфера, конверсии RGBA↔HSVA↔HSLA | **нет**: буфер осмыслен только для изображений → helper |

Разделение не машинальное — вот границы, проведённые вручную:

- **Хаффман не сведён в один модуль.** В `inflate.js` он канонический через count/symbol
  (puff, RFC 1951, LSB-first), в `jpg-format.js` — через mincode/maxcode/valptr (T.81
  Annex F, MSB-first). Это два представления одной идеи, заданные двумя спецификациями
  вместе с их битовыми порядками. Общая абстракция потребовала бы переписать горячий
  цикл обоих кодеков ради общего имени — та же ошибка, что `fillBufferWithRGB`, только
  с другой стороны.
- **Битовые читатели остались при своих форматах.** `BitLSB` неотделим от DEFLATE,
  `BitMSB` — от JPEG (он снимает стаффинг `FF00` и распознаёт маркеры).
- **Конверсии цветовых схем не поехали в `algorithm/`.** RGB↔HSL концептуально общий,
  но здешние функции работают in-place над `Uint16Array` из чередующихся каналов 0..65535.
  Скалярный вариант — это вторая реализация той же математики, то есть ровно тот дрейф,
  ради устранения которого всё и затевалось. Кандидат на вынос — когда появится
  не-графический потребитель (например, разбор CSS-цветов в `string/`).
- **`idctBlock` и `fdct` остались в JPEG**, в `algorithm/dct8.js` уехало только само
  преобразование. Деквантование, округление, клиппинг по разрядности и раскладка по
  страйду плоскости — это JPEG, а не DCT.

Вынос проверен с двух сторон: побайтовая эквивалентность выхода кодеков до и после
(26 проверок) и независимая проверка самих алгоритмов — `inflate` против `node:zlib`
на динамическом и фиксированном Хаффмане, `crc32`/`adler32` на контрольных векторах.

## 4. Матрица целей

### 4.1. Какая матрица — решает папка

| исходник лежит в | матрица | комментарий |
|---|---|---|
| `.@nodejs/**`, `.@bun/**`, `.@deno/**` | **nodejs** | bun/deno сначала транслируются в node-API (§6.6), но артефакты всё равно `nodejs*` |
| всё остальное | **es** | node-only примитивы (`Buffer`, `process`) пробуются на portable-rewrite; не вышло — цель `unsupported`, линт советует перенести файл в `.@nodejs/` **[готово]**: переносимо переписываются только `Buffer.alloc/allocUnsafe(n)` (§6.7g); импорт `node:*` в es-цели — `unsupported` |
| `@.typescript/**` | та же матрица **+ `@ts`-цели** | §4.4 |

Артефактов для браузеров и прочих движков нет: **только `es*` и `nodejs*`**.

### 4.2. es-матрица

`es6` = ES2015 … `es16` = ES2025.

| target | синтаксис | модули | что шимируется |
|---|---|---|---|
| `es3@cjs` | ES3 | cjs | всё из ES5+ (`JSON`, `Object.keys`, `Array.prototype.forEach/map/indexOf`, `Function.prototype.bind`, `String.prototype.trim`, `Date.now`, `Array.isArray`) и ниже. Getters/setters, `Object.defineProperty` → **unsupported** |
| `es5@cjs` | ES5 strict | cjs | всё из ES2015+ (`Map/Set/WeakMap`, `Promise`, `Symbol` (approx), `Object.assign`, `Array.from/of/find`, `String.prototype.startsWith`, `Number.isInteger`, `Math.imul/clz32/trunc`, `Object.entries/fromEntries`, `flat`, `globalThis`, `TextEncoder/Decoder`, `queueMicrotask`, `structuredClone` (ограниченно)) |
| `es6@mjs` | ES2015 | esm | всё из ES2016+ (`**`→`Math.pow`, `includes`, `padStart`, `Object.values`, `flat`, `at`, `Object.hasOwn`, `findLast`, `toSorted`, `Object.groupBy`, `Promise.withResolvers`, Set-методы, Iterator helpers) |
| `es6@cjs` | ES2015 | cjs | как `es6@mjs` |
| `es16@cjs` | ES2025 | cjs | ничего; только инлайн + esm→cjs |
| `es16@mjs` | ES2025 | esm | ничего; **канонический singlefile** |

Принципиально не шимируется (цель → `unsupported` с причиной в отчёте): `BigInt` (< es11),
`Proxy`, `WeakRef`/`FinalizationRegistry`, `SharedArrayBuffer`/`Atomics`, lookbehind /
`v`-флаг / модификаторы в RegExp, top-level `await` в cjs. Генераторы и `async`/`await`
для es3/es5 — §11, M4b.

**[допущение]** для `es5@cjs` TypedArray/`DataView`/`ArrayBuffer` — нативные
(IE10+, node 0.10+); для `es3@cjs` их использование → `unsupported`.

### 4.3. nodejs-матрица

Top-level код может быть ≥ nodejs21. Синтаксические профили заведены в
[profiles.js](.devdeps/downgrade/src/profiles.js) как «редакция + возможности сверх неё»
(nodejs13 = ES2019 + поля классов, BigInt, разделители в числах, `import.meta`,
`import()`); runtime — по версии node в [runtime/features.json](.devdeps/downgrade/src/runtime/features.json).
Числа — по памяти о node.green, **перепроверить** (§12 п. 30). Встроенные модули для
nodejs5/nodejs13 выводятся без `node:` (`require("crypto")`): префикс в `require` —
только с node 14.18 **[готово]**.

| target | синтаксис | модули | node-API |
|---|---|---|---|
| `nodejs5@cjs` | ES5 strict (нативны `Promise`, `Map/Set`, `Symbol`, TypedArray, `Object.assign`; нет деструктуризации, default/rest/spread — понижаются) | cjs | без `node:`; `Buffer.alloc/from` → шим поверх `new Buffer` (< 5.10); `fs/promises` → `fs` + свой promisify; `util.promisify` (< 8) → шим; `crypto.randomFillSync` (< 7.10) → `randomBytes`; `TextEncoder`/`URL`/`queueMicrotask` — шимы; `globalThis` → `global` |
| `nodejs13@cjs` | ES2019 + class fields, `BigInt`, `import.meta`, dynamic `import()`; **без** `?.`, `??`, `??=`, private methods | cjs | без `node:` (< 14.18); `timers/promises`, `stream/promises` (< 15) → promisify; `AbortController` (< 15) → шим; `structuredClone` (< 17) → `v8.serialize/deserialize` |
| `nodejs18@cjs` | ES2022 + `findLast` | cjs | `node:` ок; `fetch` есть; `toSorted`/`Object.groupBy`/`Promise.withResolvers`/Set-методы/Iterator helpers — шимы |
| `nodejs21@cjs` | ES2024 + import attributes | cjs | `Promise.withResolvers`, `Array.fromAsync`, Set-методы, Iterator helpers, `Promise.try`, `RegExp.escape`, `Float16Array` — шимы; `node:sqlite` (22.5) → unsupported |
| `nodejs21@mjs` | ES2024 | esm | как выше; канонический singlefile движкового кода |

### 4.4. `@.typescript` — дополнительные `@ts`-цели **[готово]**

Из `@.typescript/<тема>/<file>.ts` получаются:

- **вся обычная матрица** (§4.2 или §4.3): типы стрипаются, дальше как для JS;
- **`es3@ts`/`es5@ts`/`es6@ts`/`es16@ts`** или **`nodejs5@ts`…`nodejs21@ts`**: singlefile
  `.ts`, **типы сохранены**, `import`/`export` сохранены (TS всегда ESM), синтаксис и
  runtime-примитивы понижены, helper'ы заинлайнены. Формат — *erasable-only TS*
  (без `enum`/`namespace`/parameter properties; `enum` → объект + тип), чтобы артефакт
  шёл под `node --strip-types` и проходил `tsc --erasableSyntaxOnly`.

Модульная система в имени `@ts`-цели не указана: её решает `tsconfig` потребителя.

Что получилось (§6.7h): `.ts`-исходник даёт всю обычную матрицу — типы стираются, и
дальше это обычный JavaScript; `@ts`-цели собираются с сохранёнными типами и
запускаются под `node` как есть. Проверено сравнением с самим node: его стриппер и
наш дают один и тот же результат, а `@ts`-артефакт (и `.min`) node запускает.

Что теряется по дороге: тип у того, что понижение переписало. У поля класса,
ставшего присваиванием в конструкторе, аннотации не остаётся, у образца в подписи —
тоже. Артефакт остаётся erasable TS, но типизирован беднее исходника. Имена в
`.min` у `@ts`-цели не сокращаются: `typeof x` в типе ссылается на значение, а типы
в областях видимости не участвуют — переименование увело бы такую ссылку.

## 5. Раскладка артефактов

Папка цели создаётся **там, где лежит исходник**, и только там, где исходники есть:
`<dirname(исходник)>/<target>/`. Внутри — по два файла на исходник.

```
png.@image/
  png-format.js                      ← исходник: es16, ESM, импортирует helper и algorithm/
  README.md
  es16@mjs/
    png-format.js                    ← канонический singlefile: исходник + инлайн
    png-format.min.js
    package.json                     ← {"type":"module"}          (генерируется)
  es16@cjs/  es6@mjs/  es6@cjs/  es5@cjs/  es3@cjs/
    png-format.js  png-format.min.js  package.json

image/
  buffer-helper.js                   ← артефактов НЕТ: инлайнится в png/jpg/gif и эффекты
  grayscale-effect.js
  es16@mjs/grayscale-effect.js       ← с заинлайненным buffer-helper.js
  es16@mjs/grayscale-effect.min.js

algorithm/
  crc32.js  inflate.js  dct8.js  lzw.js  adler32.js  deflate-stored.js
  es16@mjs/crc32.js                  ← algorithm/ — тоже сниппеты, свои артефакты есть
  es16@mjs/crc32.min.js

.@nodejs/.5/crypto.nodejs@21/
  crypto.js
  nodejs21@mjs/  nodejs21@cjs/  nodejs18@cjs/  nodejs13@cjs/  nodejs5@cjs/
    crypto.js  crypto.min.js  package.json     ← {"type":"commonjs","engines":{"node":">=5"}}

@.typescript/math.@num/
  geometry.circle.ts
  es5@cjs/geometry.circle.js   es5@cjs/geometry.circle.min.js
  es5@ts/geometry.circle.ts    es5@ts/geometry.circle.min.ts

.t9n/ru/png.@image/README.md         ← только документация, артефактов нет
```

Семантика `.@nodejs/.5/crypto.nodejs@21/`: движок nodejs, контекст «бэкпорт для node 5»,
модуль `crypto` с API node 21. Исходник при этом написан на es16+ (инвариант 2).

Текущий масштаб: 26 сниппетов → 156 целей → в пределе 312 файлов артефактов. Сейчас
собирается **130 целей — 260 файлов в 59 папках** (все es16, es6 и es5, кроме
`cos.js` с его BigInt; es3 — у тех сниппетов, которым не нужны дескрипторы

## 6. Инструмент `@slnknrr/downgrade`

### 6.1. Принципы

- Vanilla **Node.js ≥ 21**, **zero dependencies** (тесты — `node:test`).

- Детерминизм: стабильный порядок обхода, стабильные имена сгенерированных

### 6.2. Размещение и запуск **[готово]**

### 6.3. Командная строка **[готово]**

Форма обычная для такого рода инструментов — команда, пути, флаги:

```
downgrade <команда> [пути…] [флаги]
```

| команда | что делает |
|---|---|
| `tree` | дерево импортов, codeHash каждого файла, treeHash; по каждой цели — собирается ли (`*` pending, `×` unsupported, `!` ошибка) и почему |
| `lint` | структурные инварианты §2; исходник обязан разбираться парсером |
| `emit` | собрать артефакты |
| `update` | `lint` → `emit` → сводка; обычный прогон перед коммитом |
| `minify` | минифицировать файл в stdout |
| `hash` | rawHash / codeHash / дерево файла |

Пути — файлы или папки, без них команда работает по всему репозиторию:

```
downgrade emit png.@image/
downgrade emit png.@image/png-format.js algorithm/
downgrade tree --json
```

Флаги вместо отдельных команд: `--check` (ничего не писать, сверить с диском),
`--force`, `--prune` (удалить артефакты без исходника **или без собираемой цели**),
`--targets=es16@mjs,es16@cjs`, `--why` (причины pending/unsupported по каждой паре),
`--json`, `--stat`, `--quiet`, `--report=файл` (отчёт о сборке: `.json` — машинный,
иначе Markdown для сводки задания в CI).

Пути сопоставляются с результатом `scan()`, а не с файловой системой напрямую:
`downgrade tree image/` не наткнётся на папку артефактов и не примет заметку в
`.js` за исходник. Путь, не давший ни одного файла, — ошибка, а не тихий пропуск.

npm-скрипты — тонкие обёртки: `test`, `update`, `emit`, `tree`, `lint`,
`minify` и `downgrade` (сквозной проброс). **Аргументы через npm идут после
`--`**: `npm run emit -- png.@image/ --force`; без разделителя npm забирает их
себе. Поэтому режимы — флаги, а не восемь отдельных скриптов.

Коды выхода: `0` ок, `1` расхождения/ошибки линта/ненайденный путь,
`2` внутренняя ошибка. `pending` и `unsupported` — не ошибка: артефакт не
создаётся, строка уходит в отчёт. Но если от такой цели на диске остался
артефакт прошлых сборок, это расхождение (`orphan`): он больше не соответствует
дереву, `--check` падает, `--prune` удаляет.

### 6.4. Хеш дерева и пересборка **[готово]**

Три величины ([hash.js](.devdeps/downgrade/src/hash.js)):

- **`rawHash`** — sha256 байтов файла. Меняется от правки комментария. Нигде в решении
  о пересборке не участвует, только для отладки.
- **`codeHash`** — sha256 **нормализованного** текста (§6.5): без комментариев, с
  выброшенными лишними пробелами.
- **`treeHash`** — sha256 по телу вида

  ```
  dg1 tool=0.1.0 target=es6@mjs
  png.@image/png-format.js 7c2d…
  image/buffer-helper.js   e8a2…
  algorithm/crc32.js       802f…
  algorithm/inflate.js     019d…
  builtin node:fs
  ```

  Дерево обходится **через import/export** ([graph.js](.devdeps/downgrade/src/graph.js)),
  ровно так, как его потом обойдёт линкер: что попало в дерево — участвует в сборке,
  значит участвует и в хеше. Спецификаторы берутся из потока токенов, а не регулярками:
  `'./x.js'` внутри комментария или строки импортом не является.

**Решение о пересборке** **[готово]**: собрать заново в память и сравнить с тем, что
лежит на диске. Отдельного кеша или lock-файла нет — **артефакт сам себе манифест**.
Состояний пять:

| состояние | что значит | что делает `emit` | что делает `--check` |
|---|---|---|---|
| `same` | совпадает байт в байт | ничего | ок |
| `missing` | файла нет | пишет | ошибка |
| `stale` | штамп указывает на другое дерево — **код изменился** | пересобирает | ошибка |
| `tampered` | штамп тот же, но код внутри не тот, что дают исходники | пересобирает | ошибка |
| `drifted` | штамп тот же, код тот же, **отличаются только комментарии** | ничего | ок, отметка |
| `orphan` | цель больше не собирается (pending/unsupported), а артефакт лежит | расхождение; `--prune` удаляет | ошибка |

Версия инструмента входит в тело treeHash (`tool=0.2.0`), поэтому новая версия
пересобирает всё: при переходе 0.1.0 → 0.2.0 (понижение, runtime-блок, строка
`lowered` в штампе) все 42 старых артефакта были пересобраны, у es16 изменились только
штамп и версия.

Последние два различаются нормализацией: `minify` выбрасывает комментарии, поэтому
`minify(a) === minify(b)` означает «та же программа, другой текст вокруг». Это третья
роль минификатора — отличить правку руками от безобидного расхождения.

`drifted` — прямое следствие правила «правка комментария не пересобирает артефакт»:
комментарии внутри артефакта какое-то время отстают от исходника, пока какая-нибудь
правка кода не вызовет пересборку. Это осознанный размен, а не недосмотр: альтернатива —
пересобирать 252 файла из-за запятой в комментарии.

Отсюда требование к генератору быть детерминированным (инвариант 7) — иначе «не
изменилось» не отличить от «изменилось незаметно».

`dg1` — версия схемы хеширования. Меняется вместе с нормализацией или форматом штампа,
иначе старые артефакты будут ошибочно считаться актуальными.

sha256 выбран не случайно: репозиторий живёт на sha256-объектах, второй алгоритм рядом
был бы лишней сущностью.

### 6.5. Минификатор **[готово]**

Одна механика на две задачи ([minify.js](.devdeps/downgrade/src/minify.js) поверх
[tokenize.js](.devdeps/downgrade/src/tokenize.js)):

- `minify(src)` → текст для артефакта `<name>.min.js`;
- `normalize(src)` → ровно тот же текст, и его sha256 — это `codeHash`.

Что делается: комментарии выброшены; пробелы схлопнуты до минимума, нужного чтобы
токены не слиплись; **перевод строки между токенами сохранён ровно там, где он был**.

Последнее — не экономия усилий, а условие корректности. От перевода строки зависит ASI:
`return\nx` и `return x` — разные программы. Точно решить, где перевод значим, умеет
только парсер; сохраняя все переводы как есть, мы получаем заведомо ту же программу и
всё ещё нечувствительный к форматированию хеш (отступы, выравнивание, пустые строки и
пробелы вокруг операторов схлопываются). Перевод строки **внутри выброшенного
комментария** тоже считается — иначе `return /* \n */ 1` сменил бы смысл.

Чего минификатор **не** делает: свёртки констант, удаления мёртвого кода,
переписывания выражений.

**Короткие имена — отдельным шагом** ([mangle.js](.devdeps/downgrade/src/mangle.js)),
и только для `.min`: из обычного текста считается `codeHash`, а он обязан меняться от
переименования переменной — иначе правка кода не пересобрала бы артефакт. Поэтому
сокращение живёт не в `minify()`, а поверх разбора и областей видимости, в `emit`.

Сокращаются параметры, локальные переменные, `catch`-параметры и имена импортов. **Имена
функций и классов — нет** (§12 п. 21): `.name` и `.constructor.name` — часть поведения
кода. Это касается и переменной, которой имя даёт присваивание: у `const f = () => {}`
`f.name === "f"`, и такое имя тоже остаётся. Ключи свойств — не привязки, их не трогает
ни один шаг; экспортируемое имя остаётся экспортируемым (`export { a as adler32 }`).
Файл с прямым `eval(…)` не сокращается вовсе: тот видит локальные имена по буквам.

Имена выбираются по графу конфликтов: две привязки конфликтуют, если общее имя
что-нибудь поймает (одна область; или между ссылкой и объявлением объявлено третье).
Раздаются жадно, от самых частых привязок к редким, — самое короткое достаётся тому,
кто чаще встречается. Проверка своя и обязательная: в переименованном тексте заново
считаются области видимости, и последовательность объявлений и ссылок в порядке текста
обязана совпасть с исходной — иначе имя кого-то поймало, и лучше упасть.

Вместе это даёт **−48 %** на здешних артефактах (было −35 % на одних пробелах).

Минификатор **проверяет сам себя**: результат токенизируется заново, и последовательность
значений токенов вместе с расстановкой переводов строк обязана совпасть с исходной.
Не совпало — исключение, а не тихо испорченный артефакт.

Регулярка отличается от деления по предыдущему значимому токену — обычная эвристика
однопроходных сканеров. Она врёт на `if (x) /re/.test(s)` и `{}/re/`, где нужен разбор
выражения; такой код в репозитории не встречается, а если появится — самопроверка
поймает.

**Почему два артефакта, а не один.** Обычный нужен, чтобы в артефакт можно было
заглянуть и отладить его на месте; `.min` — чтобы им пользоваться. Минифицировать
на лету у потребителя нельзя: артефакт по определению самодостаточен и не
предполагает сборки на стороне.

### 6.6. Штамп артефакта **[готово]**

```js
/* generated by @slnknrr/downgrade 0.1.0 — target es6@mjs
   do not edit: run `npm run emit`

   tree dg1 7c2d7d252c971bfa…64 hex
     png.@image/png-format.js     9c1b…
     image/buffer-helper.js       e8a2…
     algorithm/crc32.js           802f…
     algorithm/inflate.js         019d…
     algorithm/deflate-stored.js  f684…
     algorithm/adler32.js         e21c…

   codeHash считается по тексту без комментариев: правка комментария
   не делает артефакт устаревшим. */
```

В `.min`-варианте штамп — единственный уцелевший комментарий: он приписывается
**после** минификации. Шапка исходника (комментарий с описанием) сохраняется следом за
штампом в обычном артефакте и выбрасывается в `.min`.

Если понижение что-то сделало, в штампе есть строка **`lowered:`** — проходы и
содержимое runtime-блока **[готово]**:

```
   lowered: class-members, runtime: privSet privGet
   lowered: optional-chaining, portable-buffer, runtime: bufferAllocUnsafe
```

Она выводится из дерева и версии инструмента и в хеш не входит — это подсказка
читателю, чем артефакт отличается от исходника.

### 6.7b. Линкер **[готово]**

Берёт дерево из `graph.js`, вырезает из каждого файла операторы import и export и
склеивает модули зависимостями вперёд: сперва то, что ни от кого не зависит, последним —
корень. Шапка корня поднимается наверх, чтобы артефакт называл себя с первой строки.

Резка идёт **по тексту**, по смещениям токенов, а не пересборкой из токенов: иначе из
артефакта пропали бы все комментарии, ради которых обычный (не `.min`) вариант и
существует.

**Окончательные имена [готово].** Склеенные модули живут в одной области видимости,
поэтому каждая привязка верхнего уровня получает имя, уникальное на весь артефакт:

- объявление сохраняет имя, если оно не занято другим модулем и если никакой другой
  модуль не ссылается на глобальное с таким именем (иначе объявление затенило бы, скажем,
  `Symbol` и для него); занятое — `имя$2`;
- относительный импорт становится **именем того, что импортируется**: ссылки в теле
  переименовываются прямо в него, промежуточных `const b = a` больше нет (они стояли
  после всех модулей и попадали в TDZ, если модуль звал импорт при инициализации);
- импорт `node:*` — один на (модуль, имя) во всём дереве; раньше два модуля с
  `import { readFileSync } from 'node:fs'` дали бы двойное объявление;
- `var` из блоков верхнего уровня тоже модульный — учитывается (токенный разбор его
  не видел).

Переименование идёт по областям видимости (§6.7e): меняются ровно ссылки на эту
привязку, а не одноимённая переменная цикла во вложенной функции. Раньше, без парсера,
конфликт имён был отказом. Исходник, который не разбирается, — `LinkError`.

Отказывается линкер на `export … from`, `export *`, `import * as` относительного модуля,
`export default` не от имени, деструктуризации на верхнем уровне, импорте имени, которого
источник не экспортирует, и имени, объявленном дважды (импортом и объявлением).

Для CJS линкер добавляет `'use strict'`: ESM строгий всегда, CommonJS — нет, и без
директивы артефакт под `require()` получил бы другую семантику, чем исходник.

### 6.7c. Парсер **[готово]**

Рекурсивно-нисходящий, поверх готового токенизатора, имена узлов и полей — ESTree,
чтобы AST читался без словаря тем, кто видел acorn или Babel.

Разбирается весь ES2025, встречающийся в живом коде: классы с приватными полями и
статическими блоками, деструктуризация, optional chaining, генераторы, async/await,
шаблоны с вложенными подстановками, регулярные выражения, BigInt, модули с
атрибутами импорта. Проверено на всех 38 живых файлах репозитория (включая сам
инструмент): 61 тип узлов.

Нет: аннотаций TypeScript (M5), JSX, `with`. Про это парсер говорит вслух, а не
разбирает наугад.

**Диапазоны важнее самого AST.** У каждого узла есть `start` и `end` — абсолютные
смещения в исходнике. Это и определило архитектуру всего, что дальше.

Что исправлено в M3, когда на парсер встали проходы **[готово]**:

- **зарезервированные слова** (`default`, `class`, `let`, `static`, `await`, …) больше
  не принимаются как имена переменных и параметров — но остаются законными именами
  свойств (`o.default`, `import { default as x }`). Без этого `function f(default)`
  разбирался молча, и es16-артефакт `prelude.rust@1/option.js` не загружался вовсе;
- **диапазоны узлов в скобках**: у `a + (b)` конец бинарного выражения стоял до `)`,
  у `(a).b` начало обращения — после `(`. Замена по такому диапазону оставила бы
  лишнюю скобку. Теперь проверяется не только каждый оператор, но и каждое выражение:
  вырезанный по диапазону текст обязан разобраться в структурно то же поддерево;
- `-a ** 2` (ранняя ошибка языка), rest-параметр с запятой после, `a?.b\`\``, `new a?.b()`;
- `yield` и `await` — операторы только внутри генератора / async-функции (и `await` на
  верхнем уровне модуля), иначе — зарезервированные слова;
- U+2028/U+2029 внутри строкового литерала законны (ES2019) — токенизатор считал
  такую строку незакрытой.

**Баг в walk.js [исправлен].** Поле `expression` стояло в списке «заведомо не узлов»
(у стрелки это булев флаг), и обходчик **никогда не заходил внутрь ExpressionStatement
и ChainExpression**. Всё, что стояло на walk, — проверки диапазонов, сбор узлов,
«весь код разбирается» — не видело добрую половину кода.

### 6.7d. Почему принтера файла не будет

Первоначальный план на M1 был «парсер + принтер, round-trip `parse(print(ast)) ≡ ast`».
От принтера файла целиком решено отказаться, и вот почему.

Напечатать файл из AST — значит потерять всё, чего в AST нет: комментарии, пустые
строки, выравнивание таблиц констант, рамки `══` в шапках. Инструменты вроде Babel
решают это «прикреплением комментариев к узлам» — эвристикой, которая работает
в большинстве случаев и разваливается ровно там, где комментарий стоит между
узлами или внутри выражения. В репозитории, где комментарии несут половину смысла
(см. любой из кодеков), это неприемлемо.

Вместо этого: **замена текста в диапазонах узлов**. Проход понижения находит узел,
строит для него новый текст и заменяет исходный кусок; всё остальное переносится
байт в байт. Ровно так уже работает линкер, который вырезает import/export и
сохраняет комментарии бесплатно.

Следствия:

- принтер нужен, но только для тех поддеревьев, которые проход построил сам, —
  это десятки строк на конструкцию, а не полноценный кодогенератор;
- комментарии внутри понижаемой конструкции теряются (её текст заменён целиком);
  комментарии вокруг — нет;
- диапазоны обязаны быть точными, иначе замена испортит соседний код. Поэтому в
  тестах стоит проверка: текст каждого оператора, вырезанный по его диапазону,
  разбирается сам по себе в узел того же типа.

Так и сделано **[готово]** — [rewrite.js](.devdeps/downgrade/src/rewrite.js). Проход
говорит, какой узел на что заменить; текст замены строится из уже заменённых детей
(`ctx.text(child)`), так что вложенное (`a?.b ?? c?.d`) понижается за один обход снизу
вверх. Три вещи движок делает за проходы:

- **скобки** — у замены есть приоритет, у места — требуемый; не дотягивает — в скобки.
  Узел, стоявший в скобках, при переносе в другое место берёт приоритет без них;
- **ASI** — замена в начале оператора, начинающаяся с `(` или `[`, после оператора
  без `;` получает `;` впереди, иначе склеилась бы с ним в вызов;
- **временные переменные** — `ctx.temp(node)` заводит свежее имя и `var` в ближайшей
  функции (первой строкой её тела), у стрелки с телом-выражением тело становится
  блоком, у инициализатора поля — IIFE-стрелкой; верхнеуровневые уходят в runtime-блок.
  Выражение в параметре по умолчанию получает временную из внешней функции: `var` тела
  параметрам не виден.

### 6.7e. Области видимости (M1b) **[готово]**

[scope.js](.devdeps/downgrade/src/scope.js) поверх AST: области (модуль, функция,
стрелка, блок, for, switch, catch, класс, static-блок, инициализатор поля), привязки
с объявляющими идентификаторами и ссылками, глобальные (свободные) имена, `arguments`
как неявная привязка ближайшей обычной функции. `var` всплывает до функции, функция в
блоке — блочная (модуль строгий). Ссылки разрешаются после сбора всех объявлений.

Отвечает на три вопроса: глобально ли имя в этом месте (`Math.pow` вставляется, только
если `Math` не затенён; шим для `Map` — только если `Map` глобальный); какие имена
заняты (свежие `__dg_*` ни с чем не столкнутся); где все вхождения привязки
(переименование с разворачиванием `{ a }` → `{ a: b }`, `import { a }` → `import { a as b }`,
`export { a }` → `export { b as a }`).

У объявления класса по спецификации две привязки — снаружи и изнутри, — но названы
они одним идентификатором, переименовать одну без другой нельзя; поэтому внутренняя
заводится только у класса-выражения.

Проверено двумя свойствами на живом коде: каждый идентификатор классифицирован ровно
одним способом (объявление, ссылка, имя свойства/метки), и **если переименовать все
>500 локальных привязок пяти слинкованных кодеков в `__rN`, они выдают те же байты**.

Известное упрощение: параметры и тело функции — одна область. По спецификации при
параметрах с умолчаниями у тела своя область для `var`; расходится только в
`function f(a = x) { var x; }`, где `x` в умолчании мы относим к `var` тела.

### 6.7f. Понижение синтаксиса (M3, M4) **[готово для es6, es5, es3]**

[lower.js](.devdeps/downgrade/src/lower.js) — конвейер над слинкованным кодом:

1. разобрать и найти всё, чего цель не умеет: каталог возможностей с годом стандарта —
   [features.js](.devdeps/downgrade/src/features.js), профиль цели —
   [profiles.js](.devdeps/downgrade/src/profiles.js);
2. если среди этого есть непонижаемое — `unsupported` с причиной, если понижаемое, но
   прохода нет, — `pending` с этапом. Непонижаемое важнее: его не исправит никакой этап;
3. проходы — **от новых возможностей к старым** (ES2022 раньше ES2016): понижение
   нового порождает старое (`??=` → `??`, async → генератор), наоборот не бывает;
   порядок проверяется при загрузке. После каждого прохода текст разбирается заново;
   проход повторяется, пока его возможности остаются (вложенный rest), не более 8 раз;
4. переносимый Buffer и шимы (§6.7g);
5. **проверка результата тем же детектором**: если в тексте осталось что-то новее
   цели, это ошибка прохода, и сборка падает, а не кладёт на диск артефакт, который
   не загрузится. Это и есть «проверка грамматикой» из §7.2 — без скачивания старых node.

Проходы ([passes/](.devdeps/downgrade/src/passes/)):

деструктуризации, `super` в том, что уезжает из класса, `new.target` в
инициализаторах, `super(…)` не отдельным оператором при полях производного класса,
вычисляемые ключи полей, `__proto__:` и `super` после spread, async-стрелка со
сложными параметрами, читающая `arguments`,
`yield` внутри выражения (`f(yield a)`), `for-in` с `yield` внутри, выход из `try`
с `finally` в генераторе, `for await` и async-генераторы (M6 — им нужен Promise),
именованные группы, если код читает `.groups`,
вычисляемое имя метода класса, `new.target` в классе, наследование от встроенного
(`class X extends Array`) в ES5, замыкание в цикле с `break`/`continue`/`return`
внутри тела. `unsupported`: BigInt, lookbehind, флаги `d`/`v`, модификаторы
регулярок, top-level await, `import.meta` в CJS, `import()`, атрибуты импорта;
для es3 вдобавок — аксессоры, `Object.defineProperty`, `Object.freeze`,
TypedArray/DataView и WeakMap: дескрипторов свойств в ES3 нет вовсе.

Проверено исполнением: исходник и понижённый код запускаются в `node:vm`, результаты
обязаны совпасть — вместе с порядком и числом побочных эффектов, `this` у методов,
TypeError на чужих приватных полях, микрозадачами async; «оба упали одинаково»
считается пустой проверкой и не засчитывается. Весь живой код: артефакты кодеков —
и es6 (ESM и CJS), и **es5** (обычный и `.min`) — дают те же байты, что исходники;
`option.js` на WeakMap ведёт себя как на `#x`. es5-артефакт кодека — это сразу
классы, for-of, деструктуризация, шаблоны, spread, block-scoping, полифил Symbol и
шимы ES2015 в одном файле: сошёлся байт — сошлось всё вместе.

Семантические отличия, о которых надо знать (§12 п. 26): spread копирует источник, когда
до него дошло вычисление литерала, а помощник — после вычисления всех аргументов;
функция в инициализаторе поля не получает имя поля (`x = function () {}` → `name` пуст);
у async-функции другие стеки ошибок.

Отличия, которые добавляет M4 (§12 п. 32):

- **мёртвой зоны нет**: обращение к `let` до объявления даёт `undefined`, а не
  ReferenceError, — `var` всплывает;
- **повторное присваивание `const` не запрещено**: после понижения это обычная `var`;
- **итератор не закрывается**: `break` из `for-of` не зовёт `it.return()`;
- **класс всплывает как `var`**: обращение к имени класса до его объявления даёт
  `undefined`, а не ошибку;
- **статика наследуется через `__proto__`**, когда нет `Object.setPrototypeOf`;
- в **es3** неперечислимого свойства не существует: метка `__esModule` в
  `module.exports` присваивается и потому видна в `Object.keys` (§12 п. 31).
  Там же: `Object.create(proto, дескрипторы)` кладёт свойства присваиванием, и
  `Object.keys` их покажет, а `Object.defineProperty` и `Object.freeze` в коде —
  `unsupported`, а не тихая заглушка.
- **одинокий хвостовой суррогат** (обломок пары в неправильной строке): режим `u`
  считает его кодовой точкой и в отрицательный класс берёт, понижённая регулярка —
  нет. Половинки пары убраны из класса намеренно: иначе при возврате движок съел бы
  эмодзи как два обычных символа, и `.{2}` совпало бы с одним. Одинокий **ведущий**
  разбирается верно — у него есть проверка «дальше не хвост»;
- **регулярка со свойством Unicode собирается через `new RegExp`**: развёрнутое
  `\p{L}` — это 684 диапазона, а в `email.js` оно встречается 34 раза. Одинаковые
  куски вынесены в константы runtime-блока, иначе артефакт был бы в десять раз
  больше. Программа та же; отличие видно только в `re.source`.
- **генератор**: `throw()` в генератор, стоящий на `yield*`, не передаётся во
  вложенный итератор, а ловится своей же таблицей `try`; `it.return(v)` закрывает
  генератор, но не выполняет `finally`; `let` внутри генератора ведёт себя как `var`
  (объявления подняты в объемлющую функцию — иначе они не пережили бы `yield`).

**Таблица Unicode.** `\p{L}` в ES5 не выразить ничем, кроме перечисления диапазонов
кодовых точек, — а перечисление надо у кого-то взять. Берётся оно у самого движка:
[tools/gen-unicode.mjs](.devdeps/downgrade/tools/gen-unicode.mjs) спрашивает node про
каждую кодовую точку подряд и складывает ответ в
[runtime/unicode-props.json](.devdeps/downgrade/src/runtime/unicode-props.json) — 45
свойств, 48 КБ, версия Unicode записана там же. Вшито намеренно: считать таблицу на
лету значило бы, что артефакт зависит от того, какой node его собрал. Свойства
вне таблицы — честный `unsupported` с именем и указанием, куда дописать.

Проверка — сравнением с оригиналом: понижённая регулярка и исходная гоняются по
корпусу строк (латиница, кириллица, греческий, ханьцзы, эмодзи, половинки пар,
адреса почты), и совпасть обязаны оба ответа — и `test`, и что именно нашёл `match`.
Отдельно так же проверены все семь регулярок `email.js` во всех собираемых целях,
включая `.min`: 1176 сравнений.

### 6.7g. Runtime-примитивы (M3, M4) **[готово для ES5–ES2025]**

[runtime.js](.devdeps/downgrade/src/runtime.js) идёт по понижённому коду и находит
свободные имена (`globalThis`, `WeakRef`), свойства свободных имён (`Object.hasOwn`) и
обращения к методам по имени (`.at`). Тип получателя статически неизвестен, поэтому
`.at` у своего объекта тоже приведёт шим `Array.prototype.at` — это безопасно: шим
ставит метод, только если его нет (§12 п. 9). Таблица —
[runtime/features.json](.devdeps/downgrade/src/runtime/features.json): год стандарта,
версия node и что делать — шим, этап или причина отказа.

Шимы — [runtime/shims/](.devdeps/downgrade/src/runtime/shims/), 30 файлов на ES5.
ES2016–ES2025: `includes`, `Object.values/entries/getOwnPropertyDescriptors`,
`padStart/End`, `Promise.prototype.finally`, `flat/flatMap`, `Object.fromEntries`,
`trimStart/End`, `globalThis`, `matchAll`, `replaceAll`, `Promise.allSettled/any` +
`AggregateError`, `at`, `Object.hasOwn`, `findLast*`, `toSorted/toReversed/toSpliced/with`,
`Object/Map.groupBy`, `Promise.withResolvers/try`, `RegExp.escape`,
`isWellFormed/toWellFormed`, методы Set. ES2015 (M4): `es2015-math` (`imul`, `clz32`,
`trunc`, `sign`, `log2`, `hypot`, гиперболические), `es2015-number`, `es2015-object`
(`assign`, `is`, `setPrototypeOf`), `es2015-array` (`from`, `of`, `find`, `fill`,
`copyWithin`, `entries/keys/values`), `es2015-string` (`startsWith`, `repeat`,
`codePointAt`, `fromCodePoint`, `raw`). ES5 — для целей es3: `es5-core`
(`Object.keys/create/getPrototypeOf`, `Array.isArray`, `Date.now`, `bind`, `trim`) и
`es5-array` (`forEach`, `map`, `filter`, `reduce`, `indexOf`, …). Каждый проверен
против встроенного: в контексте `node:vm` нативный метод удаляется, понижённый код
ставит шим, результат обязан совпасть с настоящим node.

**Полифил-сниппет.** Того, что не влезает в шим на десяток строк, в `shims/` нет:
такой полифил живёт в репозитории обычным сниппетом и собирается во все цели, как
любой другой код. Сейчас их три: `symbol/symbol.js` (Symbol как уникальные строки,
`@@iterator`), `weakmap/weakmap.js` (WeakMap и WeakSet — значение прячется в самом
ключе неперечислимым свойством) и `arraybuffer/arraybuffer.js` (ArrayBuffer, DataView
и девять типизированных массивов). У каждой папки есть файл-витрина из одних
`export … from` — одна точка входа на тему, остальные файлы папки её наполняют.
Инструмент линкует такой сниппет в режиме `inline`, заворачивает в IIFE и берёт
нативное, когда оно есть: `var Symbol = __dg_global().Symbol || box.Symbol`. Сниппет
входит в дерево артефакта и в его хеш — правка полифила пересобирает всё, что его
втянуло. Полифилу может не хватать самой цели: TypedArray и WeakMap требуют
дескрипторов свойств, поэтому в es3 они `unsupported`, а не «почти работают».

Map, Set, Promise и Reflect в таблице помечены M6: их полифилы появятся, когда
понадобятся, — сейчас в репозитории нет кода, который бы их просил.

Помощники проходов и общее для шимов (`__dg_define`, `__dg_toInt`, …) —
[runtime/helpers.js](.devdeps/downgrade/src/runtime/helpers.js). Всё это вместе с
временными переменными верхнего уровня встаёт **runtime-блоком** на место метки,
которую линкер оставляет перед первым модулем; без runtime метка исчезает бесследно,
и es16-артефакты байт в байт такие же, как до появления понижения.

**Помощник тоже чего-то хочет.** Детектор примитивов идёт по коду до того, как
runtime-блок встал на место, — сам себя помощник не поймает. Поэтому у каждого есть
список того, что ему нужно от движка без всяких «если есть»
(`HELPER_NEEDS` в [runtime/helpers.js](.devdeps/downgrade/src/runtime/helpers.js)), и
этот список проверяется той же таблицей. Так `async` в es5 честно отказывается —
«Promise (ES2015) — шим появится на этапе M6; это нужно помощнику async», — вместо
того чтобы положить на диск артефакт, который у потребителя упадёт на первой строке.

**Переносимый Buffer.** В es-цели node-only имена недоступны (`unsupported`), с одним
исключением: если все обращения к `Buffer` — это `Buffer.alloc/allocUnsafe(n)`, они
заменяются помощником — в node это по-прежнему Buffer, вне node — `Uint8Array` той же
длины. Так `secrets.python@3/token_hex.js` собирается во все es-цели и работает вне
node, а в node ведёт себя как исходник. Всё прочее от Buffer — `unsupported`.

### 6.7h. TypeScript (M5) **[готово]**

Инструменту не нужно понимать, что тип значит, — ему нужно знать, **где тип лежит**.
Из этого получаются обе задачи сразу.

Парсер с `ts: true` ([typescript.js](.devdeps/downgrade/src/typescript.js)) разбирает
типы не в дерево, а в разметку: каждое найденное место кладётся в `ast.tsRanges` парой
`[начало, конец)`. Дерево остаётся тем же самым ESTree, что и у обычного JavaScript, —
проходы понижения, области видимости и линкер про TypeScript не знают вовсе.

Разбор типа скобочный: у составных форм (`(…)`, `{…}`, `[…]`, `<…>`) конец ищется по
парной скобке, а разделители (`|`, `&`, `=>`, условный `extends ? :`) продолжают
запись. Отдельная морока — `>>`: токенизатор склеивает его в сдвиг, а в типе это две
закрывающие скобки. Там, где уже ясно, что перед нами тип, такой токен режется надвое;
в выражении (`f<T>(x)` против `a >> b`) — не режется, и аргументы типа принимаются
только с чистым `>`, так что сдвиг остаётся сдвигом.

Размечается: аннотации, параметры типа, `interface`, `type X = …`, `declare …`,
подписи перегрузок (объявление без тела), `as`/`satisfies`, `!`, модификаторы членов
класса, `implements`, индексные подписи, типовые импорты и экспорты.

[source.js](.devdeps/downgrade/src/source.js) — один вход для всего конвейера: для
`.js` это файл, для `.ts` — файл, из которого вырезаны размеченные места. Вырезается
ровно диапазон, ничего не подставляя взамен: переводы строк вокруг остаются, поэтому
номера строк почти не едут, а ASI ведёт себя как в исходнике.

Для `@ts`-целей тот же конвейер идёт с `keepTypes`: текст читается как есть, линкер
понимает `export interface` (слово `export` убирает, имени не заводит) и
`import type` (сам импорт вырезает, но модуль остаётся частью дерева — объявление типа
приедет в singlefile вместе с ним), а понижение работает поверх текста с типами.

**Только erasable TS** (§4.4): `enum`, `namespace`, `module X {}` и параметры-свойства
конструктора оставляют после себя код, а не только типы, — на них разбор падает с
объяснением. Артефакт с ними не прошёл бы ни `node --strip-types`, ни
`tsc --erasableSyntaxOnly`.

Проверка — сравнением с самим node: он умеет стирать типы, и его результат взят за
эталон. Файл запускается дважды — как `.ts` (node стирает сам) и как очищенный нами
`.mjs`; вывод обязан совпасть. Так же проверяются артефакты: `@ts` (обычный и `.min`)
запускается node'ом как TypeScript, JS-артефакт — как JavaScript.


### 6.8. Конвенция esm→cjs

```js
module.exports = png;                 // require() возвращает сам объект — DX как у ESM default
module.exports.default = png;
module.exports.png = png;
Object.defineProperty(module.exports, '__esModule', { value: true });
```

Без default-экспорта → `module.exports = { a, b }`. Живые байндинги не нужны: после
инлайна внешних импортов не остаётся. `import x from 'node:fs'` → `require('node:fs')`
или `require('fs')` по профилю **[готово]**: без префикса — для nodejs5/nodejs13.

### 6.9. Трансляция bun/deno → node

`Bun.file(p).text()` → `fs.promises.readFile(p,'utf8')`, `Bun.write` → `writeFile`,
`Bun.env`/`Deno.env.get` → `process.env`, `Deno.args` → `process.argv.slice(2)`,
`Deno.exit`/`Deno.cwd` → `process.*`, `Bun.sleep` → `timers/promises`,
`bun:sqlite` → `node:sqlite` (≥ 22.5, иначе unsupported). Неизвестный `Bun.*`/`Deno.*`,
`Bun.serve`/`Deno.serve`, `npm:`/`jsr:`/`https://` — `unsupported` с причиной. Дальше
применяется nodejs-профиль цели.

### 7.1. Предпосылки

- Репо создаётся на Codeberg с **Object Format = sha256** (Forgejo ≥ 7.0; после создания

  40-символьные хеши; `git` ≥ 2.29 (в `node:24-bookworm` есть).
- Секрет `ARTIFACTS_TOKEN` — для коммита артефактов ботом.

### 7.2. `artifacts.yml`

```
on: push (main) | pull_request | workflow_dispatch
container: node:24-bookworm

check   → npm run lint; npm test; npm run emit -- --check --report=build.md --why
          отчёт уходит и в сводку задания ($GITHUB_STEP_SUMMARY), и файлом
          (upload-artifact). Для PR это единственный результат: артефакты там
          обязаны быть уже собранными, иначе --check не сходится.
smoke   → needs check; матрица заданий, в каждом свой node (actions/setup-node),
          каждому — свой список целей:
            node 4  → es3@cjs, es5@cjs        node 13 → es6@mjs, nodejs13@cjs
            node 5  → nodejs5@cjs             node 18 → nodejs18@cjs
            node 6  → es6@cjs                 node 21 → nodejs21@cjs, nodejs21@mjs
            node 24 → es16@cjs, es16@mjs
          Список готовит node из контейнера (tools/smoke.mjs --list), грузит —
          уже нужный движок (tools/smoke-load.cjs, он на ES5 и CommonJS: под
          node 4 модуль бы не разобрался). .min грузится наравне с обычным.
          Риск: бинарники 4/5/6 собраны под старую glibc и могут не стартовать
          на bookworm. Если так — эти уровни остаются на проверке грамматикой,
          которую инструмент и так делает при сборке (§6.7f).
commit  → только push в main, needs smoke, if: diff непустой && actor != bot
          git add '**/es*@*' '**/nodejs*@*'; commit "chore(artifacts): regenerate [skip ci]"
```

На PR артефакты **не коммитятся** — только проверяются и выкладываются как CI-artifact.

Благодаря treeHash пересборка идёт только по тем деревьям, где реально поменялся код:
правка README или комментария в шапке кодека не даёт ни одного изменённого файла,
и шаг `commit` просто не срабатывает.

  (`function f({ id })`), а `block-scoping` считал занятыми имена из соседних
  функций и переименовывал `function Dog` внутри IIFE в `Dog$2` — имя класса
  пропадало из `.name` (§12 п. 21).

  файл не загружался даже в node) переименован в `default_value` — других правок в нём нет.

Чего нет: генераторов и регулярок для es5/es3 (M4b), TypeScript (M5), CI (M0b/M2b).
Оставшиеся цели отмечаются `pending` с точной причиной (`флаг u у регулярки → ES5:
проход — этап M4b (строка 9)`) или `unsupported` — их 25, и это BigInt, lookbehind,
дескрипторы свойств в es3 и node-only имена в es-целях.

Тестов — 190 (было 64). Кроме обычных проверок грамматики там свойства, которые
ловят молчаливое враньё: диапазон каждого оператора **и каждого выражения**, вырезанный
из исходника, разбирается сам по себе в структурно то же поддерево; AST исходника
совпадает с AST его минифицированной версии; каждый идентификатор классифицирован
областями видимости; переименование всех локальных привязок кодеков не меняет их
выход; каждое понижение и каждый шим проверены исполнением против исходника и
против настоящего node; кодеки, понижённые до es5, дают те же байты, что исходники;
а то, что лежит в репозитории, сверяется с `render` побайтно, а не только по хешу
дерева, — иначе правка самого инструмента прошла бы мимо тестов.
