# Перестройка: инструмент в корень, режимы @bundle/@cjs/@mjs/@custom

Решения владельца от 2026-09-23, зафиксированные по итогам разбора (восемь раундов
вопросов). Открытых развилок почти не осталось — что осталось, собрано в §6.
Реализация не начата; коммитов в репозитории нет, так что перестройка обходится без
переписывания истории.

---

## 1. Раскладка и режимы

| решение | как именно |
|---|---|
| режимы | `@bundle` (IIFE, без экспорта), `@bundle_cjs`, `@bundle_mjs`, `@cjs`, `@mjs`, `@custom`/`@custom_*` |
| IIFE | **только у `@bundle`**. В `@bundle_cjs`/`@bundle_mjs` обёртки нет: код на верхнем уровне плюс `module.exports` / `export` |
| форма `@bundle` | по `var` на каждый экспорт, имена — ровно как в `export` исходника: `var encode, decode; void function(){ encode = …; decode = … }();` |
| `@bundle*` | бандл **каждого файла по отдельности**: зависимости из чужих тем заинлайнены, итоговые файлы друг о друге не знают |
| `@cjs`/`@mjs` | модули рядом: копии зависимостей лежат в папке цели **с сохранением структуры от корня репозитория**, сам файл — в корне цели |
| runtime в `@cjs`/`@mjs` | **дублируется в каждый файл**, который его зовёт; общего модуля нет — любой файл можно унести поотдельности |
| `.min` | только у канона (`es16@bundle_mjs`, `nodejs21@bundle_mjs`) и у `@bundle_ts`/`@ts` |
| `@custom` | инструмент не собирает и не удаляет, но **учитывает**: показывает в отчёте, ловит конфликт с собираемой целью того же имени; внутри обязателен `CUSTOM_NOTICE.md`, без него — ошибка линта |
| миграция | сегодняшние 59 папок (319 файлов) **сносятся целиком**, дальше полный прогон |

```
png.@image/
  png-format.js                          исходник
  es5@bundle/png-format.js               IIFE, var на каждый экспорт
  es5@bundle_cjs/png-format.js           module.exports, без IIFE
  es5@cjs/
    png-format.js                        свой файл — в корне цели
    image/buffer-helper.js               чужая тема — путь от корня репо
    algorithm/crc32.js
    package.json
  es5@custom/                            руками; внутри CUSTOM_NOTICE.md
```

## 2. Матрица целей

| матрица | цели |
|---|---|
| **es** (комбинаторика, `mjs` только с es6+) | `es3@cjs`, `es3@bundle`, `es3@bundle_cjs`, `es5@cjs`, `es5@bundle`, `es5@bundle_cjs`, `es6@cjs`, `es6@mjs`, `es6@bundle`, `es6@bundle_cjs`, `es6@bundle_mjs`, `es16@cjs`, `es16@mjs`, `es16@bundle`, `es16@bundle_cjs`, `es16@bundle_mjs` — 16 |
| **nodejs** (явный список) | `nodejs5@cjs`, `nodejs13@cjs`, `nodejs18@cjs`, `nodejs18@mjs`, `nodejs21@mjs` — 5 |
| **deno** | `deno1@mjs`, `deno2@mjs` — заводятся сразу (версии уточняемы) |
| **браузер** | `chromium49@bundle`, `chromium80@bundle`, `chromium120@bundle_mjs` — заводятся сразу |
| **typescript** | `@bundle_ts` и `@ts` |

Правило `mjs` с es6+: `export` — синтаксис ES2015, в профиле es3/es5 его нет.

**Движковая тема `X.nodejs@N`** означает «API этого модуля версии N». Цели — **строго
младше N** (для `crypto.nodejs@21` это `nodejs5@cjs`, `nodejs13@cjs`, `nodejs18@cjs`,
`nodejs18@mjs`) плюс канон `nodejs21@bundle_mjs`. Пустые `crypto.nodejs@5/13/18`
остаются заготовками.

Набор целей ограничивается **секцией в `package.json`** (её видят и человек, и CI),
флаги CLI перекрывают её для разового прогона.

## 3. `*_NOTICE.md`

- Ищутся **всегда**, это работа `custom-downgrade.js`.
- **Корень задаёт базу, папка — добавку.** `VANILLA_NOTICE.md` в корне даёт es-матрицу
  всем недвижковым темам; `TYPESCRIPT_NOTICE.md` в папке добавляет ей `@ts`-цели.
- **У движков наследования нет: reset & override.** Движковая папка описывается
  top-level; корневая база внутрь неё не проникает, es-целей у движкового кода не бывает.
- Нет NOTICE в движковой папке — матрица берётся из имени движка (`.@nodejs` → nodejs).
  Есть — цели даёт каждый NOTICE, а из имени папки уже не выводятся; внутри движковой
  ветки NOTICE **наслаиваются**: `.@nodejs/NODEJS_NOTICE.md` +
  `.@nodejs/buffer.nodejs@18/DENO_NOTICE.md` = обе матрицы у `buffer.nodejs@18`.
- Содержимое файла пока не разбирается — **важен факт существования**. Формат тела
  (строки вида `файл as имя-у-получателя` для переброски CI) прорабатывается позже.

## 4. Инструмент

| решение | как именно |
|---|---|
| размещение | 88 файлов плоско в корне, **имена как есть**, без префикса: `parse.js`, `scope.js`, `link.js`, `arrow.js`, `at.js`… |
| как отличается от сниппетов | **top-level `.js` — всегда инструмент или служебное**; сниппетов в корне не бывает. Это дописывается в CODE_STRUCTURE.md как правило |
| граница | `downgrade.js` — библиотека + CLI про один файл (понизить в профиль/формат, minify, дерево импортов). `custom-downgrade.js` — всё репозиторное: обход, NOTICE, матрица, раскладка, `emit`/`lint`/`update`/`prune`, отчёт |
| версия в штампе | инструмент бандлится и минифицируется **сам собой в памяти** (файла не создаётся), sha256 результата и есть версия; она же живёт константой. Правка комментария в инструменте перестаёт пересобирать репозиторий |
| самопонижение | **да, как тест**, в папку `!test/` (в обработку `custom-downgrade.js` не попадает, в git не коммитится): `!test/nodejs18@cjs` — сам инструмент; `!test/<сниппет из тем *.es@*>/` — цели `es3@cjs`, `es3@bundle`, `es6@mjs`, `es16@bundle_mjs`. Сниппет выбирается детерминированно, от хеша списка тем |

## 5. Хеши, шимы, сеть

**Штамп.** В шапке файла внутри `@cjs`/`@mjs` — **оба хеша**: собственное дерево файла
и дерево всей цели. Каждый хеш пишется **связкой** `md5:<…>, sha256:<…>, sha384:<…>` —
везде, включая построчное дерево. md5 в связке намеренно.

**Шимы становятся сниппетами** — в ту же перестройку. Тема — эксклюзив, поэтому:

- полифилы примитивов идут в тему **по году редакции**: `array.es@2015/`, `array.es@2023/`,
  `string.es@2017/` и так далее;
- не-примитивы и stdlib (Math, JSON) — в `prelude.es@<год>/`;
- существующие `symbol/`, `weakmap/`, `arraybuffer/` **переименовываются** по той же
  схеме (`symbol.es@2015/`, `weakmap.es@2015/`, `arraybuffer.es@2015/`);
- кастомные методы, а не полифилы (`isTypedArray` из `typedarray-verify-sure.js`),
  остаются в своей предметной теме — `typedarray/` (или `arraybuffer/`).

**Deno.** У deno-целей пишется **source map** (`.js.map`) — только у них; остальные цели
без карт. URL-импорты разрешены (в deno-папках) и **скачиваются**: цикл «скачать →
обработать», как со своим кодом. Коммитится **только лок-файл** с URL и хешами, сам кэш
в игноре.

## 6. Что осталось открытым

1. **Содержание `*_NOTICE.md`** — разбирается позже, сейчас важен только факт файла.
2. **Имя vanilla-маркера.** В `README.txt` он назван `VANILLAJS_NOTICE.md`, в репозитории
   лежит `VANILLA_NOTICE.md`. Беру за канон `VANILLA_NOTICE.md`, `README.txt` поправлю —
   скажите, если наоборот.
3. **Форма API `downgrade.js`.** Предлагаю: `downgrade({ entry, profile, format, root, readFile })`
   → `{ files: [{ path, code, map? }], tree, lowered, problems }`; для `@bundle*` в `files`
   один элемент, для `@cjs`/`@mjs` — несколько. Если форма важна — поправьте.
4. **Версии в матрицах deno и chromium** (`deno1/deno2`, `chromium49/80/120`) — взяты
   как черновые, до первого исходника в соответствующей папке.

## 7. Следствия, которые стоит знать заранее

- **Объём.** 16 es-целей + шимы, ставшие сниппетами (ещё ~30 тем), дают порядка
  **1200–1500 файлов артефактов** против 319 сегодня. Репозиторий становится
  преимущественно сгенерированным — это осознанный выбор («всё явно»).
- **Source maps — новый слой.** Сегодня понижение правит текст в диапазонах узлов и
  позиций не ведёт; чтобы выдать `.js.map`, правки придётся сопровождать сдвигами.
  Это самая дорогая часть перестройки после нового режима линкера.
- **CI понадобится сеть** — кэш deno-модулей не коммитится, а лок-файл только сверяет
  хеши. Раньше сборка была полностью офлайновой.
- **Дублирование runtime** в `@cjs`/`@mjs` раздувает папки, но шимы guarded (ставят
  метод, только если его нет), так что многократная установка безопасна.
- **Инвариант «в папке артефактов только сгенерированное»** меняется: `@custom*`
  исключается из него и из `linguist-generated` в `.gitattributes`.

## 8. Порядок работ

1. Уплощение инструмента в корень, разделение `downgrade.js` / `custom-downgrade.js`,
   версия-из-хеша. Раскладка пока старая, тесты зелёные.
2. Новые режимы: форма `@bundle` без экспорта, режим «модули рядом» для `@cjs`/`@mjs`,
   новая `TARGET_RE`, `@custom` с маркером.
3. Матрицы и NOTICE-логика в `custom-downgrade.js`, секция набора целей в `package.json`.
4. Шимы → темы `*.es@<год>`, переименование `symbol/`, `weakmap/`, `arraybuffer/`.
5. Снос всех папок целей и полный прогон; `!test/` и тест самопонижения.
6. Deno: URL-кэш с лок-файлом и source maps.
7. Документы: CODE_STRUCTURE.md (правило top-level, новые режимы, классы тем),
   BACKLOG.md §4–§7, README.txt, `.gitattributes`, CI.
